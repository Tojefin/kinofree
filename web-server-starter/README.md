# Web Server Starter

Набор скриптов для запуска локального веб-сервера с сайтом KinoFree.
Поддерживаются **Windows, macOS и Linux**.

## Запуск

- Скачайте скрипт для своей системы и поместите его в отдельную папку.
- Запустите скрипт и дождитесь открытия сайта.
- Закройте терминал или нажмите Ctrl+C, чтобы остановить запущенный сервер.

### Windows

При первом запуске лаунчер загружает портативный Python и сборку сайта из
GitHub Pages. Следующие запуски используют установленный сайт, поэтому
доступность GitHub не мешает локальному запуску.

```cmd
windows-start.bat
```

Для проверки и установки обновления:

```cmd
windows-start.bat --update
```

Если обновление недоступно или архив повреждён, лаунчер запускает установленный
сайт. Замена сайта выполняется после проверки архива, с резервной копией и откатом
при ошибке замены.

Запуск сервера без открытия браузера:

```cmd
windows-start.bat --no-browser
```

Параметры `--update` и `--no-browser` можно использовать вместе.
Браузер открывается после проверки готовности HTTP-сервера. Если этот сайт уже
обслуживается на выбранном порту, повторный запуск использует существующий сервер.

Порт задаётся переменной `PORT` в начале BAT. Лаунчер автоматически обновляет
`server.py`, созданный его прежней версией, чтобы тот учитывал переданный порт.
Пользовательский `server.py` сохраняется.

Windows BAT распространяется с **CRLF**, без BOM. Для прямого скачивания Raw
CRLF сохраняются в самом Git blob; `.gitattributes` запрещает нормализацию этого
файла в LF. Скрипт macOS/Linux использует LF.

### macOS и Linux

Используйте `mac-linux-start.sh`. Требуются установленные Python 3 и curl.
Этот скрипт проверяет обновления при каждом запуске.

## Проверки Windows-лаунчера

Из корня репозитория:

```powershell
.\web-server-starter\tests\test-windows-start.ps1
```

По умолчанию тесты загружают портативный Python с python.org. Можно передать
папку уже установленного embeddable Python:

```powershell
.\web-server-starter\tests\test-windows-start.ps1 -PythonDirectory C:\tools\python-embed
```

Тесты создают отдельные временные установки, используют локальный HTTP fixture
и заменяют открытие браузера файловым сигналом. Проверяются повторный запуск,
работа без GitHub, обновление старого `server.py`, сохранение пользовательского
сервера, установка с нуля, успешное обновление и отклонение повреждённого или
небезопасного архива.
